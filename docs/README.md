# API documentation

The [published API reference](https://carlos-sweb.github.io/z-number/) is generated by Zig 0.17.0 directly from the source declarations and `///` documentation comments.

Generate it locally:

```sh
zig build docs
python3 -m http.server 8000 --directory zig-out/docs
```

Open <http://localhost:8000/>. Serve the directory over HTTP: the generated viewer loads WebAssembly and a source archive. Generated files remain in the ignored `zig-out/docs` directory.

Every push to `master` runs the [Pages workflow](../.github/workflows/docs.yml), checks the ReleaseSafe tests and example, builds the documentation and publishes it. A failed check prevents publication. The workflow can also be run manually from GitHub Actions.

## Memory and error contracts

`ZNumber` borrows its allocator. Creating, copying and deinitializing a number does not allocate or release formatting results. Every formatting result is an owned `[]u8`; free it using the allocator supplied to that method, including special-value results such as `"NaN"`.

`parseFloat` performs no heap allocation. `parseInt` needs no heap for magnitudes fitting `u64`; larger integer prefixes use temporary arbitrary-precision storage and can return `error.OutOfMemory`. `stringToNumber` can also allocate for nondecimal literals. Invalid parsing returns NaN.

Formatting can return `error.RangeError` for invalid numeric arguments and `error.OutOfMemory` for allocation failures. `toIndex` reports `error.RangeError`; checked Zig conversions document their own bounds. Optional numeric `null` means an omitted argument.
